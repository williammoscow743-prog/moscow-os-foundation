## Purpose

This document defines the visual and behavioral standards for toasts, the in-app notification center, and status badges across Moscow OS.

## Scope

Covers the Notifications module referenced in the System Overview's module list and notification-related UI used throughout the product. Does not cover email or external notification channel design, which is out of scope for this Design System.

---

## 1. Toasts

Toasts are transient, non-blocking messages confirming the result of a user action (for example, "Project created").

| Property | Value |
|---|---|
| Position | Bottom-right of viewport, stacking upward for multiple toasts |
| Background | `bg-surface-raised` |
| Elevation | `elevation-3` |
| Corner Radius | `radius-md` |
| Max Width | 360px |
| Auto-dismiss | 5 seconds for informational toasts; error toasts require manual dismissal |

| Type | Left Accent Bar | Icon |
|---|---|---|
| Success | `semantic-success` | Check circle |
| Error | `semantic-danger` | Alert circle |
| Warning | `semantic-warning` | Alert triangle |
| Info | `semantic-info` | Info circle |

## 2. Notification Center

The notification center is accessed via the bell icon in the top navigation (`navigation.md`, DS-011, Section 1) and opens as a panel anchored to that icon, using overlay styling from `color-system.md` (DS-003), Section 1, at `elevation-3`. Unread notifications are indicated with a `brand-build` dot; the bell icon itself carries a numeric badge for unread count when greater than zero.

## 3. Notification List Item

Each item displays: an icon indicating the source module, the notification text (`text-body-sm`), a relative timestamp (`text-caption`), and, for unread items, a `brand-build` indicator dot at the leading edge. Clicking an item navigates directly to the relevant entity and marks it read.

## 4. Badges

Badges are compact status indicators used inline within tables, cards, and lists (for example, a task's status: "In Progress", "Overdue").

| Status Category | Background | Text |
|---|---|---|
| Neutral | `bg-surface-overlay` | `text-secondary` |
| Success | `semantic-success-surface` | `semantic-success` |
| Warning | `semantic-warning-surface` | `semantic-warning` |
| Danger | `semantic-danger-surface` | `semantic-danger` |
| Info | `semantic-info-surface` | `semantic-info` |

Badges use `text-caption` at `weight-semibold`, `space-1` vertical and `space-2` horizontal padding, and `radius-full` corners.

## 5. Notification Preferences

Users control which notification types generate toasts, notification-center entries, or external (email) delivery via Settings, per the System Overview (DOC-100), Section 6.12. The design of preference controls follows the Switch component in `forms.md` (DS-008), Section 7, one per notification category.

## 6. AI-Originated Notifications

Notifications generated by the AI Workspace (for example, a proactive flag on an at-risk project) carry the same AI-attribution treatment defined in `cards.md` (DS-009), Section 6, so their origin is never ambiguous.

## 7. Accessibility

Toasts are announced via `aria-live="polite"` (or `"assertive"` for errors) so screen reader users are notified without needing to discover the toast visually. The notification center's unread count is exposed via `aria-label` on the bell icon, not conveyed by the numeric badge alone.
